Docker — это технология для упаковки кода и всех его зависимостей в изолированную среду, называемую контейнером. В отличие от виртуальных машин, контейнеры используют ядро хост-системы, что делает их легкими и быстродействующими. Базовая структура Docker состоит из образа - immutable шаблон с файловой системой и настройками, контейнера - запущенный экземпляр образа, Dockerfile текстовый набор инструкций для сборки образа и реестра хранилище для распространения образов.  

Манифест образа (Image Manifest) — это JSON-документ, описывающий содержимое и параметры запуска конкретного образа. Он содержит уникальные идентификаторы и дайджесты хэши слоев файловой системы, из которых собирается образ, а также указывает на конфигурацию команды запуска, переменные окружения, порты. В случае мультиархитектурной сборки используется список манифестов Manifest List, который выступает как указатель, направляющий Docker-демон к нужному манифесту в зависимости от архитектуры процессора целевой машины, например, отдавая версию для x86 на сервере и версию для ARM на борту робота. 

В создании робота Docker применяется на трех ключевых этапах. На этапе разработки он решает проблему несовпадения окружений, позволяя всей команде работать в одинаковой изолированной среде с нужными версиями драйверов, библиотек и промежуточного ПО вроде ROS, независимо от операционной системы ноутбука разработчика. На этапе тестирования и симуляции Docker используется для запуска физических движков и алгоритмов в чистых контейнерах, что обеспечивает воспроизводимость результатов и предотвращает конфликты зависимостей симулятора с другими проектами на машине. На этапе развертывания на реальном железе Docker гарантирует, что протестированный код запустится на встроенном компьютере робота точно так же, как на стенде разработчика, так как в контейнер упакована вся необходимая runtime-среда, что критично важно для работы с разнообразными и часто ресурсоограниченными одноплатниками.
